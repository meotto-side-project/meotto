# MEOTTO 보안 감사 (공격자 시점, 읽기 전용)

입력: 호출 프롬프트가 알려 주는 감사 대상(도메인, 경로). 지정이 없으면 `backend/src/main/java` 전체. 코드를 수정하지 않는다.

도메인이 아직 없으면 `global/security`, `global/exception`, `global/infrastructure`만 감사하고 그 사실을 밝힌다.

## 점검 항목

### 인증과 권한
- **인증 우회**: `SecurityConfig`에 등록되지 않은 엔드포인트 (현재 `/admin/**` 외 전부 허용), ADMIN 권한 체크 누락
- **IDOR**: 요청 파라미터로 `userId`를 받는 API (타인 데이터 접근)
- **소유자 검증 누락**: `userId` 비교 없이 뮤테이션 수행
- **소프트딜리트 우회**: `AndDeletedAtIsNull` 필터 누락 (삭제된 데이터 노출)
- **JWT**: 알고리즘 혼동, 만료 미검증, 시크릿 하드코딩 (`JwtProperties` 외 참조)

### 노출
- 스택트레이스가 에러 응답에 포함되는지 (`GlobalExceptionHandler`)
- 다른 유저의 FCM 토큰, PII가 응답이나 로그에 포함되는지
- 설정 파일(`application*.yml`)의 시크릿 하드코딩

### 비즈니스 로직
- **경쟁 조건**: 동시 요청으로 중복 생성·중복 처리 가능 여부 (예: 같은 도장 중복 전송)
- **페이지네이션 우회**: `size=-1`, `size=999999`
- **파일 업로드**: `FileStorageService`의 파일 타입, 크기 제한, 경로 순회, S3 키에 사용자 입력이 그대로 들어가는지
- **알림 오용**: 다른 유저에게 임의 FCM 푸시를 보낼 수 있는지
- **스케줄러 중복**: 분산 환경에서 `@Scheduled` 중복 실행

## 결과 형식

```text
## Critical (즉시 수정)
| 취약점 유형 | 파일:라인 | 공격 시나리오 | 수정 방법 |

## High
| 취약점 유형 | 파일:라인 | 공격 시나리오 | 수정 방법 |

## Medium / Low
| 취약점 유형 | 파일:라인 | 설명 |

## 방어 코드 제안
[Critical/High 항목에 대한 구체적 수정 코드]

## 점검하지 못한 것
- ...

## 판정: ✅ 안전 / ⚠️ 수정 권장 / ❌ 수정 필수
```

모든 지적은 `파일:라인`과 근거를 함께 제시한다. 코드로 확인하지 못한 가설은 지적하지 않고 "점검하지 못한 것"에 적는다.
