# 스플래시 · 온보딩 · 인증

IA: 멋토 → 온보딩 → 소셜 로그인 → 홈 | (칭찬 요청 공유 링크로 비회원 진입 → 토마토 보내기 → 비회원 홈)

| F-04 | 비회원 진입 | 앱 내 별도 진입 버튼 없음. 친구가 칭찬을 요청하며 공유한 링크를 눌러 토마토 보내기 페이지로 진입, 링크를 공유한 친구에게 도장을 보낸다. 이후 흐름은 [send-stamp.md](send-stamp.md) F-24.                                                                                                                                                                                                                                            |

## 온보딩 슬라이드 카피

1. "친구의 멋을 발견해봐요!"(`멋을 발견` 강조색) / "일상 속 무심코 지나쳤던 친구의 모습에서 반짝이는 멋을 발견해보세요."
2. "토마토 도장에 마음을 담아 친구에게 전달해보세요!"(`토마토 도장` 강조색) / "평소 말로는 전하기 쑥스러웠던 마음을 귀여운 토마토 도장에 담아 전해보세요."
3. "받은 토마토를 차곡차곡 모아요!"(`받은 토마토` 강조색) / "친구들이 보내준 토마토 도장을 나만의 칭찬판에 기록하고 언제든 다시 확인해요."

## 가입 프로필 설정 화면 (F-03)

- 프로필 설정 화면: 상단 뒤로가기와 제목 `프로필 설정`, 원형 프로필 사진(연필 버튼, 라벨 `프로필 사진`), `이름*` 입력(placeholder `이름을 입력해주세요.`), `멋토 아이디*` 입력(서버가 제안한 아이디가 미리 채워져 있음), 하단 `완료` 버튼. 입력창에 포커스가 있으면 지우기(X) 버튼이 나타난다.
- `이름`과 `멋토 아이디`는 필수(`*`), 프로필 사진은 선택이다. 화면 라벨은 `이름`이고 서버 필드는 `nickname`이다.
- 이름 규칙은 [mypage-settings.md](mypage-settings.md)에서 확정됨: 2~10자, 한글/영문/숫자/공백만 허용(이모지·특수문자 금지). 멋토 아이디 규칙은 아래 결정 사항 참고.
- 프로필 사진을 누르면 사진 선택 화면으로 이동한다: 뒤로가기, 제목 `프로필 사진`, 우측 상단 확인(체크) 버튼, 미리보기 원과 안내 `사진을 선택하세요.`, 3열 앨범 그리드. 앨범은 네이티브 앨범 접근으로 불러온다. 카메라 촬영 UI는 Figma에 없다.

## AC

- 온보딩 마지막 장(3번째)에서만 `멋토 시작하기`가 노출되고, 누르면 로그인 화면으로 이동한다.
- 로그인 성공 시 회원 홈([home.md](home.md))으로 이동한다.
- 칭찬 요청 공유 링크로 진입 시 토마토 보내기 페이지([send-stamp.md](send-stamp.md) F-24)로 이동하며, 링크를 공유한 친구에게 도장을 보낸다.
- 가입 시 입력하는 이름(서버 필드 `nickname`)은 2~10자이며 한글/영문/숫자/공백만 허용한다. 범위를 벗어나거나 이모지·특수문자가 포함되면 가입이 완료되지 않는다 ([mypage-settings.md](mypage-settings.md) 이름 규칙과 동일).
- 가입 시 프로필 사진은 선택이며, 업로드 제한(최대 10MB, jpg/png/webp/heic)은 [mypage-settings.md](mypage-settings.md)의 프로필 사진 업로드 제한과 동일하다.
- 프로필 입력 화면에서 뒤로가기를 누르면 로그인 화면으로 돌아간다(별도 확인 팝업 없음, 가입 취소 API 없이 서버 데이터는 그대로 남는다). 이름·아이디를 입력하지 않고 나가도 입력을 다시 시작할 수 있다.
- 프로필 입력을 마치지 않고 이탈한 뒤 같은 소셜 계정으로 다시 로그인하면, 로그인 화면이 아니라 다시 프로필 입력 화면으로 이동한다(이미 완료한 가입처럼 바로 홈으로 가지 않음).
- 처음 가입한 회원이 프로필 설정 화면에서 이름과 멋토 아이디를 모두 입력해야 `완료`로 가입을 마칠 수 있다.
- 멋토 아이디가 아이디 규칙을 벗어나면 가입이 완료되지 않는다.
- 가입 `완료` 후 회원 홈([home.md](home.md))으로 이동한다.
- 이미 가입을 마친 회원이 프로필 설정 화면에 접근하면 홈으로 이동한다.
- 이름 규칙 위반, 아이디 중복·형식 오류가 나면 해당 입력창 아래에 오류 문구가 보이고 그 입력창 테두리가 빨간 계열로 강조된다.
- 서버 오류(5xx, 네트워크 실패)가 나면 토스트로 안내하고 입력값은 유지한다.

## 결정 사항

- 멋토 아이디 규칙: 3~30자, 영문(대소문자)/숫자/마침표(`.`)/언더스코어(`_`), 마침표 연속·시작·끝 금지. 아이디는 서버가 랜덤으로 제안하며(Plan C-2) 사용자는 그대로 쓰거나 고칠 수 있다. 가입 후 변경은 불가하다. 아이디는 다른 사용자와 중복될 수 없다.
- 가입 프로필 설정 화면에서는 `@`를 쓰지 않는다. 서버가 제안한 아이디는 입력창에 미리 채워진 값으로 보여준다(placeholder 아님). `@아이디` 표기는 내 정보(계정관리 시트), 친구 정보처럼 아이디를 보여주는 화면에만 붙인다.
- 프로필 사진 선택은 네이티브 앨범 접근으로 한다(웹 UI로 앨범을 만들지 않는다). 마이페이지 프로필 변경 시트도 같은 방식을 쓴다. 업로드 제한은 [mypage-settings.md](mypage-settings.md)의 제한과 같고 이미지 비율 제한은 없다(BE 구현 기준).
- 화면의 이름 입력 라벨은 `이름`이다. Figma의 가입 화면과 마이페이지 프로필 변경 시트 모두 `이름`이며 `닉네임` 표기는 없다. 서버 필드는 `nickname`이다.

- 로그인 상태 유지는 `access_token`/`refresh_token` HttpOnly 쿠키로 한다(Plan C-1). 웹은 토큰을 저장하지 않고 `credentials: include`로 요청한다. 앱은 로그인 성공 시 웹이 보낸 `AUTH_LOGIN_SUCCESS`로 네이티브에 로그인 플래그를 저장하고, 시작할 때 이 플래그로 분기한다(쿠키 + 네이티브 플래그). (MEO-54, 사용자 확정)
- 오류 문구: 이름 규칙 위반 "이름은 2~10자의 한글, 영문, 숫자, 공백만 쓸 수 있어요.", 아이디 형식 오류 "아이디는 3~30자의 영문, 숫자, 마침표(.), 밑줄(_)만 쓸 수 있고 마침표는 처음·끝·연속으로 쓸 수 없어요.", 아이디 중복 "이미 사용 중인 아이디예요.", 서버 오류 토스트 "잠시 후 다시 시도해 주세요."(3초), 사진 접근 권한 거부 "사진 접근 권한이 필요해요."
