# SDD 도입 효과 측정 기록

하네스로 만든 PR과 수동으로 만든 PR을 같은 항목으로 비교한다. 기록은 `/log-metrics`로 추가한다.

- 표본이 적어 통계가 아니라 방향성 참고용이다.
- 기능 난이도와 작업자가 달라서 비교는 **AC당 값**으로 한다.
- 값이 없으면 `-`. 추정해서 채우지 않는다.

## 열 정의

| 열 | 의미 |
|---|---|
| 날짜 | 기록한 날짜 |
| 방식 | `manual` 또는 `harness` |
| PR / Linear | PR 번호, Linear ID |
| Spec / AC수 | 대상 Spec 파일과 F-ID, AC 개수 |
| 작업시간(h) | 실제 작업 시간 (자가 기록, 대기 제외) |
| 이슈 시작→완료 | Linear `startedAt`→`completedAt` (대기 포함) |
| PR 열림→머지 | 리뷰 대기를 포함한 경과 시간 |
| 변경줄(+/-) | PR 추가/삭제 줄 수 |
| 초안 수정률 | 하네스만. AI 초안 이후 수정 줄 ÷ 초안 줄 |
| 리뷰 후 수정률 | 첫 리뷰 이후 커밋의 변경 줄 ÷ PR 전체 변경 줄 (공통 비교값) |
| AC 충족 | `spec-verifier` 채점. 충족/전체 (미검증 포함) |
| 누락 AC | 머지 후 발견된 누락 건수 (Bug 이슈, 리뷰 코멘트) |
| 토큰/비용 | 하네스만. `/cost` 합계 |
| 스킬 보수 | 기간 내 `.claude`, `CLAUDE.md` 변경 커밋 수 / 줄 수 / 시간(분) |
| 비고 | 특이사항 |

## 해석 메모

- 방식별 행이 각각 3개 미만이면 평균을 결론으로 쓰지 않는다.
- 하네스의 유지보수 비용은 도입 초기에 높고 점차 줄어드는지 추이로 본다.
